## Which layout a visitor gets

The page is static. It renders the **Mac layout** by default, so every platform is listed with no JavaScript. A small inline script runs before first paint (no flash). It reads `navigator.userAgentData?.platform` or `navigator.userAgent`:
- iPhone/iPod (not iPad) → `data-device="ios"`
- Android → `data-device="android"`
- anything else → stays Mac

CSS shows the matching block. Don't fetch, and don't redirect. iPad and other tablets get the Mac layout.

## File check (the fold)

- First line: the file name in mono, the size and the release date.
- `dl` with two entries, the file SHA-256 and the signing-certificate SHA-256. Don't name the signer until it has been read from the certificate (unconfirmed). Each value sits in a `.hash` box (mono 13px, `--code-bg`, 1px inset `--line`, breaks anywhere) with a **복사** button beside it. The button is 44px tall and a fixed 8.5em wide, so the box beside it doesn't change width when the label turns to "복사했어요". Copied state: check icon in `--ok` and "복사했어요" for 2 s, announced through a `role="status"` region.
- **터미널로 확인하기** (`h4`, top rule), then the line "Mac에서 같은 파일을 받아 터미널에서 실행해요." Two more entries, each a `pre` with its own copy button. It wraps only at spaces and after `/` (`<wbr>`), never inside a word:
  - `shasum -a 256 ~/Downloads/<file>`
  - `apksigner verify --print-certs ~/Downloads/<file>` (Android SDK build-tools; the "Signer #1 certificate SHA-256" line). Not `keytool -printcert -jarfile`, which reads only v1 signatures.
- Last line: "두 값 중 하나라도 다르면 설치하지 말고 이 페이지에서 다시 받아요." and a link to the GitHub release.
- **Values**:
  - The file name, size, date and file SHA-256 must come from the real release asset at build time. The mockups' file hash and date are stand-ins. I couldn't find the APK release on GitHub (`equipe-labs/equipe-app` has no releases; `equipe-labs/equipe` v0.103.69 has no `.apk`).
  - The certificate SHA-256 starts `f6884e26` and ends `041a87`, matching the squad record (`android-signing-key`). Its full value should be read with `apksigner` from the release APK before shipping.
