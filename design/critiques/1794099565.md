[blocker] B · 데스크톱 일지 — 팀이 일한다는 증거가 시간순 문장 일곱 줄을 읽어야 이해되는 기록으로 바뀌었습니다. 승인 요청·승인 완료·배포 완료까지 함께 있어 지금 누구 차례인지도 흐립니다 — 현재 작업과 승인 대기 한 건을 먼저 보여주고 지난 기록은 접으세요.

[blocker] C · 데스크톱 팀 목록과 승인 카드 — 승인 카드가 팀의 작업을 가립니다. 뒤에는 역할과 상태만 있고 무엇을 만드는지는 없어 ‘내 팀’보다 ‘확인 모달’이 먼저 보입니다 — 구체적인 작업명과 진행 상황을 노출하고 승인 카드를 해당 작업에 붙이세요.

[blocker] C · 모바일 첫 화면 — 서비스 소개보다 `Publish now`가 먼저 나와 처음 온 사람에게 맥락 없는 공개 결정을 요구합니다. 샘플 버튼이 실제 방문자 행동보다 강합니다 — 제목과 Mac 링크 보내기를 먼저 두고 승인 장면에는 데모임을 표시하세요.

[blocker] A·B·C · 승인 카드 본문 — “Once shared, it can’t be taken back”은 가격 페이지 공개와 되돌릴 수 없는 행위를 혼동합니다 — 실제 동작에 맞춰 공개 대상·즉시 적용되는 변경·되돌릴 수 있는 범위를 쓰세요.

[polish] B · 서체와 전체 표면 — 크림색·가는 세리프·알약 버튼의 조합은 익숙한 에디토리얼 SaaS 문법입니다. ‘불 꺼진 관제실’의 정확함을 약화합니다 — 장식적인 제목 비중을 줄이고 실제 작업 정보의 배열로 방향을 구분하세요.

[polish] C · 헤드라인 — 네 줄의 과대한 제목과 회색으로 낮춘 “You just approve.”가 핵심 약속의 위계를 뒤집습니다 — 제목을 압축하고 승인 문장을 보조 설명처럼 처리하지 마세요.

[polish] C · 신호색 — 작업 중 표시와 승인 버튼이 같은 파랑이라 ‘팀이 움직이는 상태’와 ‘내가 해야 할 행동’이 분리되지 않습니다 — 색을 더 늘리지 말고 상태는 작은 표시로, 행동은 버튼 면으로 구분하면서 작업 상태의 채도를 낮추세요.

[polish] A·C · 숫자 구간 — `222 / 20 / 1`을 거대한 세 칸으로 나누니 증거보다 랜딩 페이지의 관습적인 성과 띠로 보입니다 — “20일 동안 티켓 222개, 승인한 사람 한 명”을 실제 작업 장면에 연결하세요.

[polish] A·B·C · 대비 검증표와 제품 내부 글자 — 팔레트 조합의 AA 통과표만으로 작은 메타데이터·흐린 상태 글자·비활성 컨트롤의 실제 대비는 확인되지 않습니다 — 최종 렌더링의 크기·배경·투명도로 검사하고 일반 텍스트 4.5:1 미만은 노출 전에 수정하세요.
