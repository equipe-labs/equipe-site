## Whole

3초 시선은 A에서 ‘대형 제목→흰 CTA→분산된 카드’, B에서 ‘대형 제목→흰 공개 카드→작업 패널’, C에서 ‘대형 제목→빽빽한 기록→흰 공개 카드’로 흐른다. 세 안 모두 팀이 끝낸 실제 작업보다 광고 문구가 먼저 보이며, 레퍼런스 보드의 제품 중심 장면 대신 설명용 상자와 선이 화면을 채운다. 가로 인계·권한 분할·시간 기록이라는 배치는 다르지만, 같은 요약 카드와 공개 카드를 재배열한 수준이라 로고를 가리면 어느 에이전트 서비스에도 붙일 수 있다.

## Findings

- [blocker] 전체 6장 · 제품 증거 영역 — 실제 산출물 대신 “구현했어요”, “검증 완료”라는 자기 보고가 증거를 대신한다 — 읽을 수 있는 실제 지표·변경 화면·QA 결과를 같은 사건으로 연결하고, 그 결과를 승인 카드에 붙여라.
- [blocker] A-390 · 인계 레일 — DATA 다음이 DESIGN이고 곧바로 공개다. PM 판단·구현·QA를 지워 핵심 약속인 팀의 전체 작업을 증명하지 못한다 — 모바일에서도 다섯 단계의 결과를 남기고 설명 길이를 줄여라.
- [blocker] A-1440 · 중앙 인계 카드 — 계단식 높이와 카드 사이 선은 있지만 무엇을 넘겼는지 보이지 않는다. 빈 카드 면적만 커서 인계보다 조직도에 가깝다 — 동일 산출물이 판단·설계·구현을 거치며 바뀌는 내용을 연결 지점에 보여라.
- [blocker] A-1440 · 우측 공개 카드 — 공개 결정이 다섯 카드 끝의 부록으로 밀리고 재측정은 작은 문장에 묻힌다 — 완료된 팀 작업이 한 결정으로 모이고 다시 지표로 돌아가는 구조를 화면의 중심 관계로 만들어라.
- [blocker] B-390 · 하단 설치 CTA — iPhone 앱 보기와 Mac 링크 보내기가 긴 작업 패널과 공개 카드 뒤에 있다. 폰 첫 화면 요구를 충족하지 못한다 — 두 행동을 히어로 설명 바로 아래로 옮겨라.
- [blocker] B-1440·390 · 팀 작업 패널 — DATA·DESIGN·FRONTEND·QA를 병렬 배치해 지표가 어떤 판단을 낳았는지 사라진다. 80/20은 권한 구조가 아니라 대시보드 면적 설명으로 읽힌다 — PM 판단을 명시하고, 완료된 산출물들이 사람의 공개 결정으로 모이게 연결해라.
- [blocker] B-1440·390 · DATA 배경 크롭 — 실제 제품 화면을 너무 어둡고 작게 깔아 읽을 수 없게 만들었다. 모바일에서는 18건도 사라져 0건의 맥락이 끊긴다 — 장식용 배경 처리를 없애고 18건·iPhone 유입·0건이 함께 읽히는 실제 화면 부분을 전면에 놓아라.
- [blocker] C-390 · 구현과 공개 사이 — 데스크톱에 있던 QA 단계가 빠져 구현 직후 공개를 묻는다 — 검증 결과를 공개 직전의 필수 행으로 유지해라.
- [blocker] C-1440·390 · 사건 타임라인 — 시간·역할·상태 칩이 결과보다 먼저 읽히며, 대부분의 행이 작업했다는 문장뿐이다. 기록이 길어져도 증거는 늘지 않는다 — 시간을 보조 정보로 낮추고 각 행의 중심을 실제 산출물과 달라진 결과로 바꿔라.
- [blocker] A-390·B-1440 · 히어로 제목 — “드 / 려요”로 단어가 끊긴다. B 우측 제목도 “왔 / 어요”로 갈라져 임시 서체 문제가 아니라 폭과 줄바꿈 설계 실패다 — 잠긴 문구는 유지하고 한국어 어절 보호와 제목 폭·크기를 함께 조정해라.
- [blocker] 전체 6장 · 첫 화면 위계 — 거대한 제목이 공간을 선점하고 팀의 작업과 승인 관계를 아래나 옆으로 밀어낸다. 특히 모바일은 설명을 읽고 내려가야 제품을 만난다 — 제목 점유 높이를 줄이고 첫 화면에 실제 작업 결과와 대기 중인 결정이 함께 들어오게 해라.
- [polish] A-1440·C-1440 · 본문 여백 — A는 카드 아래가 비고 C는 왼쪽 제목과 바닥 CTA 사이가 비는 동안 작업 정보는 좁은 영역에 몰린다 — 빈 공간을 실제 산출물의 판독 크기에 배분하고 제목·증거·행동의 간격을 하나의 척도로 정리해라.
- [polish] B-390 · 두 열 작업 그리드 — 좁은 반쪽 열에서 QA 제목이 꺾이고 왼쪽 DATA 아래에는 빈 구멍이 남는다 — 모바일은 작업 순서에 맞춘 한 열로 바꾸고 카드 높이를 내용에 맞춰라.
- [polish] 전체 6장 · 보조 글자와 상태 라벨 — 흐린 회색의 작은 인계 설명·요구 사양·검증 정보가 읽기 전에 사라진다 — 실제 CSS 크기로 판독성을 확인하고 일반 텍스트 대비 4.5:1을 확보해라. 스크린샷만으로 AA 통과를 판정할 수는 없다.
- [polish] 전체 6장 · 역할 제목과 구현 설명 — ALL CAPS 역할명, `appStoreLink`, 커밋 해시, `390·KO/EN`이 내부 검수 문서를 방문자에게 노출한다 — 역할명은 보조로 낮추고 “폰에서 앱 열기와 Mac 링크 보내기 검증 완료”처럼 사용자가 이해할 결과를 앞세워라.
- [polish] B-1440·390 · “화면의 80% / 20%” 라벨 — 레이아웃 제작 의도를 제품 카피로 써놓았다 — 면적 비율을 지우고 “팀이 마친 일 / 내가 결정할 일”만 남겨라.

## Verdict

**revise** — 가장 먼저, 요약 카드 묶음을 **실제 산출물 하나가 지표→판단→설계→구현→QA를 거쳐 공개 결정에 도착하는 읽을 수 있는 장면**으로 바꿔라. 지금은 팀이 일했다는 설명만 있고, 일한 증거가 없다.
