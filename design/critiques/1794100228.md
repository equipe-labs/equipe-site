## Whole
3초 시선은 A가 제목→제품 창→다운로드, B가 세리프 제목→기록 카드→다운로드, C가 제목→파란 승인 버튼→팀 목록 순서다. A에서도 팀이 하는 일보다 창의 틀이 먼저 보이고, B는 편집물, C는 승인 위젯으로 읽힌다. Linear와 나란히 두면 제품 내부의 정보 위계가 덜 완성돼 보이며, 로고를 가렸을 때 A는 범용 업무 도구, B는 세리프 SaaS 템플릿, C는 에이전트 데모와 구별되지 않는다.

## Findings
- [blocker] A·B·C 시트 · 모바일 첫 화면 — A는 승인 카드가 화면 아래에서 잘리고, B는 작업 기록 뒤로 승인이 밀리며, C는 팀 목록이 사라진다. 어느 안도 ‘일하는 팀과 내 승인’을 함께 전달하지 못한다 — 실제 제품 흐름을 작업 두 줄과 승인 한 건으로 압축해 첫 화면에 함께 배치한다.
- [blocker] C 확대본 · 팀 목록과 승인 카드 — 작업 중 표시와 승인 행동에 같은 파랑을 써 상태·행동의 구분이 여전히 없다. 제목의 ‘점 하나’와 달리 여러 점과 큰 버튼이 동시에 강조된다 — 작업 상태는 중립색·명시적 라벨로 표현하고 신호색의 역할을 하나로 제한한다.
- [blocker] B 확대본 · 히어로 기록 카드 — 1라운드의 요청→분담→결정→승인→공개 흐름을 없애고 현재 상태 목록으로 바꿨다. 읽을 양을 줄이면서 ‘내 승인으로 일이 나간다’는 인과관계도 지웠다 — 기록 전체 대신 진행 중 작업과 승인 후 결과가 이어지는 짧은 장면을 만든다.
- [blocker] C 확대본 · 히어로 전체 — 회색 둘째 줄을 고쳤지만 제목과 승인 카드가 모두 크고 강해 팀의 존재는 여전히 배경이다. 카드의 가림만 줄였을 뿐 전체 위계 문제는 남았다 — 제목과 카드의 크기를 줄이고 실제 제품 창을 제목 아래 주 시각물로 둔다.
- [blocker] A 확대본 · 제품 창의 티켓 표 — 넓은 빈 하단, 반복되는 역할·상태, 의미가 설명되지 않은 진행 막대가 창의 대부분을 차지한다. ‘팀이 일한다’는 증거보다 관리 화면의 골격을 보여 준다 — 실제 산출물이나 최근 행동을 표시하고 빈 영역을 줄여 승인 건과 연결한다.
- [polish] A 확대본 · 제목 오른쪽 설명·다운로드 — 제목을 읽은 뒤 오른쪽으로 건너갔다가 제품 창 왼쪽으로 돌아가야 한다. 1라운드보다 창은 올라왔지만 읽는 경로는 갈라졌다 — 설명과 다운로드를 제목 아래 짧게 묶고 제목 위 여백을 줄여 제품 창 위치를 확보한다.
- [polish] B 확대본 · 제목과 기록 카드 — 거대한 세리프 제목에 비해 시간·역할·티켓 번호가 지나치게 작다. 넓은 여백이 제품을 드러내지 않고 제목을 전시한다 — 제목 크기를 낮추고 기록의 본문 크기와 행 간격을 키운다.
- [polish] B 시트 · 한국어 히어로 — 영어의 길고 좁은 세리프와 한국어 명조의 폭·행 밀도가 달라 같은 브랜드의 위계로 읽히지 않는다 — 한국어 제목의 크기·폭·행간을 별도로 설정하고 문장 단위 줄바꿈을 고정한다.
- [polish] C 확대본 · 영어 제목 — ‘team.’이 한 줄로 떨어져 핵심 명사만 고립되고 제목이 불필요하게 세로로 길어진다 — 글자 크기나 제목 폭을 조정해 ‘startup team.’을 함께 둔다.
- [polish] A·B·C 시트 · 모바일 다운로드 영역 — Mac 실행 안내, 공유 수단 설명, 링크 복사, iPhone 설명이 두 버튼 주변에 누적돼 제품 장면을 밀어낸다 — 필수 안내를 한 줄로 줄이고 공유 방법은 버튼을 누른 뒤 보여 준다.
- [polish] C 시트 · 반전된 승인 설명 섹션 — 밝은 면 전체가 승인 카드보다 강한 대비를 만들어 페이지 중간에서 시선이 끊긴다 — 섹션 배경 전환을 줄이고 승인 장면 자체에 대비를 집중한다.
- [polish] A·B·C 시트 · 승인 장면 — ‘Publish now’와 ‘Hold’가 있는 정지 상태만으로는 클릭 후 처리 중·완료·실패·보류가 어떻게 이어지는지 검토할 수 없다 — 같은 장면의 후속 상태를 제시하고 중복 승인 방지와 실패 후 재시도까지 확인한다.

## Verdict
**revise — A를 추천한다.** 가장 필요한 변경은 제품 창을 ‘작업 목록과 별도 승인 카드’에서 **팀의 실제 작업이 승인 한 건으로 이어지는 하나의 장면**으로 재구성하는 것이다. 데스크톱과 모바일 모두 그 장면이 첫 화면에서 읽혀야 한다.
