## 1. 누구를 위한 사이트인가

**메이커(maker)** — 하고 싶은 일이 손보다 많은 한 사람. 코드를 짜든 못 짜든, 말로 설명할 수 있으면 된다. ✅ ('founder/창업자' 대신 'maker/메이커', 2026-11-01)

- **지금 가장 먼저 붙잡을 사람**: Claude Code를 이미 쓰는 1인 창업자. 첫 10명은 직접 깔아 주고 매주 인터뷰한다. ✅ (North Star: 주간 승인 스쿼드 수)
- **그 사람이 사이트에서 알아야 할 것**: ① 팀 하나가 통째로 일한다 ② 중요한 건 내가 승인한다 ③ 내 Mac에서, 쓰던 Claude·ChatGPT 요금제로 돈다 ④ 지금 받을 수 있다(Mac 앱).
- **아닌 대상**: 좌석 단위로 사는 회사 구매 담당, 에이전트를 직접 조립하고 싶은 도구 애호가. ✅ (2026-11-04)

## 2. 성격 — 그리고 아닌 것

| 성격 | 뜻 | 아닌 것 |
|---|---|---|
| **차분한** | 큰소리 없이 단언한다. 일은 팀이, 결정은 내가. | 들뜬 하이프 — "10x", "혁신적인", 느낌표 |
| **정확한** | 무엇이 어떻게 되는지 명사·숫자·장면으로. 준비 중은 "준비 중"이라고. | 막연한 약속, 없는 기능 자랑 |
| **사람 편** | 권한은 늘 사람에게. 공개·발송·결제 전엔 꼭 묻는다. | "AI가 알아서 다 해요" — 사람을 지우는 말 |
| **살아 있는** | 팀이 지금 일하는 게 보인다 — 실제 앱 화면, 움직이는 보드, 실제 숫자(20일·티켓 220개). | 밋밋한 설명조, 장식용 그림 |

앞의 셋은 v1에서 정했다(✅). 넷째 **살아 있는**은 "밋밋한 설명조가 싫다"는 사람 의견(2026-10-31)에서 나와 2026-11-04에 사람이 골랐다(✅, '대담한'·v1의 '정돈된'·셋만 두기는 고르지 않음). v1의 넷째였던 **정돈된(editorial)** 은 성격이 아니라 시각 원칙으로 §4에 남긴다.

## 3. 레퍼런스

## 리브랜딩 방향 브리프 (T-521, 2026-11-08)

- **레퍼런스 한 곳:** Linear 홈(https://linear.app) 첫 화면 — 짧은 왼쪽 정렬 제목 바로 아래에 실제 제품 창을 크게 두고, 가는 선과 조용한 한 색만 쓴다. 가져오는 것은 그 구조와 절제, 가져오지 않는 것은 Linear의 로고·보라색·문구.
- **비주얼 명제:** 불 꺼진 관제실에서 팀의 불빛만 조용히 움직이고, 내 승인 한 번에 일이 나간다.
- **자유로운 것:** 색(신호색 하나 + 중립), 글꼴 짝(en·ko), 레이아웃, 섹션 순서, 제품 장면의 모양(기능·흐름은 실제 앱 그대로).
- **3초 시험:** 첫 화면에서 '팀이 이미 일하고 있고, 나는 승인만 한다'가 설명보다 먼저 보인다. 폰 방문자는 다운로드 대신 'Mac으로 링크 보내기'·'iPhone 앱 받기'가 첫 화면에 있다.

## 키 비주얼 라운드 브리프 (T-521, 2026-11-08 2라운드)

A·B·C(관제 패널·근무 일지·점 하나)는 사람이 셋 다 거절했다: "퀄리티가 아쉬워", "걍 뭔가 AI 슬롭 같아". 감도 기준은 **Cursor와 Linear**(사람이 고름)다. 다음은 페이지보다 **키 비주얼 3개**를 먼저 보이고(사람 결정), 그림은 AI 이미지 생성 도구로 만든다(사람 결정 — Codex 이미지 생성, 사람의 ChatGPT 로그인).

- **레퍼런스:** Cursor 홈(https://cursor.com) — 그림 한 장(유화 풍경) 위에 *진짜* 제품 창을 띄운다. Linear 홈(https://linear.app) — 어둠 속에 빛 받은 *진짜* 제품 화면을 두고 아주 정밀하게 다듬는다. 가져오는 것은 '그림 + 진짜 제품'의 구조와 절제, 가져오지 않는 것은 두 곳의 로고·그림·문구.
- **비주얼 명제:** 그림 한 장이 분위기를 말하고, 그 위의 진짜 앱 화면이 '팀이 이미 일하고, 내 결정 한 건이 기다린다'를 말한다.
- **바뀐 것:** 제품 장면은 손으로 그린 표가 아니라 실제 데스크톱 앱 화면(UI 지도 `equipe/design/flows/inbox/decision`)을 쓴다. 방향끼리는 그림(소재·빛·색)으로 다르다.
- **피할 것:** AI 슬롭 신호(`design/references/ai-slop/`), 브리프의 '흔한 AI 스타트업'(보라 그라데이션·빛나는 구·반짝이).

## 구조 탐색 리셋 (T-521, 2026-11-09)

사람은 AI 생성 이미지를 쓴 키 비주얼 세 안도 모두 거절했다: "다 별론데", "애초에 더 좋은 디자인을 뽑을 수 있을까", "리서치좀 많이 해줘봐". 위 키 비주얼 라운드의 **그림을 먼저 고르는 순서**는 이 최신 피드백으로 폐기한다. 이름·로고·한 줄 문구 잠금은 그대로다.

- **레퍼런스:** Cursor·Linear의 실제 제품 증거, Flighty의 실제 세계 정보 문법, Dessn·Proof의 한 장면 증명. `design/references/board.png`의 13곳과 `design/references/2026-11-08-deep-research.md`.
- **비주얼 명제:** 관제실 사진을 보여 주지 않는다. 실제 equipe의 `지표 → PM 판단 → 역할별 작업 → QA → 공개 결정 → 배포 → 재측정`이 끊기지 않고 이어지는 모습 자체가 조용한 관제실이다.
- **탐색 순서:** 같은 임시 중립색·임시 서체로 흑백 구조 20개 → 비평으로 구조가 다른 3개 → 실제 제품 크롭이 작동하는 프로토타입 → 그 뒤에만 색·서체·표면.
- **실제 근거:** 브리프의 2026-11-02 유입 리뷰 — LinkedIn 유입 18건, 대부분 iPhone 인앱 브라우저, 다운로드 클릭 0건. 현재 equipe 데스크톱의 지표·로드맵·받은함·승인 화면.
- **피할 것:** 생성 이미지를 브랜드 정체성으로 쓰기, 전체 앱 창 축소, 근거 없는 개선 수치, 결정 카드만 반복, 색·폰트·배경만 다른 세 안.

## 최종 방향 라운드 (T-521, 2026-11-10)

구조 탐색에서 남긴 세 구조를 각자의 색·서체·표면까지 입혀 완성된 방향으로 비교한다. 세 안 모두 같은 실제 사례(11/02 유입 리뷰: LinkedIn 유입 18건·다운로드 클릭 0 → PM 판단 → designer·frontend·QA → 공개 결정 → 2주 뒤 재측정)와 같은 문구를 쓴다. 규격: `design/directions/2026-11-10-final/SPEC.md`.

- **A 한 테이크** — 레퍼런스 Linear·Cursor 홈: 짧은 제목 아래 크게 띄운, 코드로 다시 그린 실제 앱 창(티켓 하나의 활동 타임라인 + 결정 카드). Geist·Pretendard, 흑연색 + 호박색 불빛 하나.
- **B 밤사이 일지** — 레퍼런스 21st.dev 상태 로그·Granola: 왼쪽 세리프 제목, 오른쪽 시각이 찍힌 작업 일지에 산출물 조각. Newsreader·Noto Serif KR·Inter·Pretendard, 먹색/종이색 + 초록 불빛 하나.
- **C 출발 안내판(과감)** — 레퍼런스 Flighty: 공항 안내판 문법의 스쿼드 상태판, '나' 줄만 노랗게 켜진다. IBM Plex Sans·Mono·Sans KR, 순흑/회백 + 신호 노랑.
- **비주얼 명제:** 제품 장면 자체가 키 비주얼이다 — 팀이 한 사이클을 끝내 놓고 내 결정 한 건만 남은 모습이 3초 안에 읽힌다.
- **폰:** 첫 화면 주 행동은 'Mac으로 링크 보내기'(공유 시트), 보조는 'iPhone 앱 받기'.

## 5. 목소리

- **짧게, 동사·장면·숫자로.** 헤드라인은 한두 문장. ✅
- **한국어는 번역하지 않고 처음부터 한국어로 쓴다.** 해요체. '당신'은 쓰지 않고 주어를 빼거나 '내'를 쓴다. ✅
