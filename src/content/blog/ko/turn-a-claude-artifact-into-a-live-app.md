Claude 채팅에서 쓸 만한 걸 만들어 봤다면, 생각보다 진짜 제품에 가까이 있지만 느낌보다는 더 멀리 있어요. 인터페이스는 작동하고, 클릭해서 둘러볼 수도 있어요. 하지만 채팅 창은 고객이 찾고, 믿고, 의지할 수 있는 곳이 아니에요.

이 가이드는 "Claude에서는 되는데"와 "고객이 쓸 수 있는" 사이의 간극이 무엇인지, 그리고 그걸 어떻게 메우는지 설명해요. 호스팅 서비스를 직접 쓰든, 앱 빌더를 쓰든, 팀에 맡기든 어떤 길에서나 적용돼요.

<p class="answer"><strong>짧은 답.</strong> 코드를 복사해 두고, 아티팩트가 흉내 내던 모든 것(데이터, 로그인, 키)을 진짜로 바꾸고, 데이터베이스와 여러분의 도메인이 있는 호스팅에 올리고, 휴대폰으로 테스트하고, 기본 분석 도구를 추가하세요. 그런 다음 실제 사람 몇 명에게 출시하세요.</p>

## Claude 아티팩트란 무엇이고, 무엇이 아닐까요

아티팩트는 Claude가 대화 옆에 만들어 주는 독립된 소프트웨어 조각이에요. 페이지, 작은 도구, 계산기, 트래커 같은 거요. Claude 안에서 돌아가기 때문에, 여러분과 링크를 받은 사람들이 아무것도 설치하지 않고 쓸 수 있어요.

그게 바로 한계이기도 해요. 아티팩트는 **작동하는 스케치**예요. Claude가 놓아둔 곳, 여러분 것이 아닌 주소에 있고, 몇 달 동안 고객의 데이터를 담도록 만들어진 게 아니라 아이디어를 보여주려고 만들어졌어요. 보통 네 가지가 빠져 있어요.

- **자기만의 주소.** `bookings.yourstudio.com`처럼 여러분의 도메인에 있고, 여러분이 통제하고 옮길 수 있는 페이지예요.
- **진짜 데이터베이스.** 많은 아티팩트가 데이터를 방문자의 브라우저나 샘플 데이터에 보관해요. 누가 브라우저를 비우면 데이터가 사라지고, 여러분도 그 데이터를 볼 수 없어요.
- **진짜 로그인과 권한.** 누가 무엇을 볼 수 있나요? 관리자는 누구인가요?
- **운영해 줄 사람.** 업데이트, 장애, 보안 수정, 그리고 "제 휴대폰에서 안 돼요"라는 메시지를 처리하는 일이에요.

이 중 어느 것도 아티팩트의 결함이 아니에요. 그저 프로토타입과 제품의 차이예요. '진짜'가 무엇인지 더 자세히 알고 싶다면 [코딩 없이 제품을 출시하는 가이드](/ko/blog/launch-a-real-product-without-code/)를 보세요.

## 1단계: 내가 만든 것 파악하기

무엇이든 옮기기 전에 쉬운 말로 적어 보세요.

1. **무엇을 하는지.** 한 문장으로요. 세 문장이 필요하다면 두 가지를 만든 걸지도 몰라요.
2. **누가 쓰는지.** 나 혼자인지, 친구 몇 명인지, 일반 대중인지요.
3. **어떤 데이터를 다루는지.** 이름? 이메일? 결제? 비공개 정보가 있나요?
4. **무엇을 가정하고 있는지.** 다른 서비스를 호출하나요? 붙여 넣은 키를 쓰나요? 샘플 데이터가 내장되어 있어서만 작동하는 건 아닌가요?

답에 따라 옮기는 일의 양이 정해져요. 아무것도 저장하지 않는 계산기는 작은 일이에요. 사람들의 연락처를 받는 예약 도구는 더 큰 일이에요. 개인정보가 있으면 보안과 개인정보 보호의 기준이 높아지니까요.

## 2단계: 코드 꺼내기

Claude에게 전체 코드를 한 번에 달라고 요청하세요. "이 아티팩트의 전체 소스를 파일 하나로 줘. 자리 표시자인 부분에는 주석으로 표시해 줘." 찾기 쉬운 곳에 저장해 두세요. 이게 백업이기도 하니, 다시 만지지 않더라도 보관해 둘 가치가 있어요.

코드를 읽을 필요는 없어요. 잘 보관해 두고, 옮겨 줄 사람이나 도구에 건네줄 수만 있으면 돼요.

## 3단계: 아티팩트가 흉내 내던 것 바꾸기

여기가 진짜 작업이에요. 1단계에서 적은 가정 목록을 하나씩 보면서, 라이브 버전은 그 대신 무엇을 하는지 정하세요.

| 아티팩트가 흉내 낸 것 | 라이브 앱에 필요한 것 |
| --- | --- |
| 페이지에 내장된 샘플 데이터 | 진짜 항목을 저장하고 재시작에도 살아남는 데이터베이스 |
| 브라우저에 저장 | 서버에 저장해서, 여러분과 사용자가 같은 데이터를 보도록 해요 |
| "링크가 있는 누구나" 접근 | 로그인, 그리고 고객과 관리자의 명확한 구분 |
| 코드에 붙여 넣은 키 | 비밀 키 저장소. 키는 코드나 채팅에 나타나지 않아요 |
| 여러분이 지켜볼 때만 실행됨 | 하루 종일 돌아가는 호스팅, 실패했을 때 알려주는 오류 보고 |

예외 상황에 대해서도 같은 질문을 해 보세요. 두 사람이 같은 시간대를 예약하면 어떻게 될까요? 이메일이 끝내 도착하지 않으면요? 방문자가 폼에 예상 밖의 내용을 입력하면요? AI 어시스턴트나 사람 리뷰어가 출시 전에 이런 걸 짚어 줘야 해요. 아무도 짚지 않으면 고객 불만으로 만나게 될 거예요.

## 4단계: 호스팅, 데이터베이스, 도메인

세 가지 배관이 아티팩트와 서비스의 차이를 만들어요.

- **호스팅**은 누구에게나, 언제든 앱을 보여줘요. 데이터가 없는 간단한 페이지는 정적 호스트에서 저렴하게 운영할 수 있어요. 로그인과 데이터가 있는 앱은 서버 코드를 실행할 곳도 필요해요.
- **데이터베이스**는 사용자가 입력한 것을 보관해요. 여러분이나 팀이 데이터를 내보낼 수 있는 걸 고르세요. 그래야 어디에도 묶이지 않아요.
- **도메인**은 여러분이 소유한 이름이고, 브라우저에 자물쇠가 보이도록 보안 인증서가 붙어요. 구입은 몇 분이면 되지만, 제대로 연결하는 데 많은 분들이 저녁 한나절을 써요.

직접 한다면 계정, 설정, 약간의 DNS를 배우게 될 거예요. 앱 빌더를 쓰면 상당 부분이 내장되어 있지만, 요금제와 게시에 관한 선택은 여전히 해야 해요. equipe에서는 팀이 호스팅, 데이터베이스, 도메인을 설정하고, 라이브로 나가거나 비용이 드는 일 전에 여러분의 승인을 요청해요. [그 승인이 어떤 의미인지](/ko/blog/is-equipe-safe-data-money-approvals/)에 대한 글도 있어요.

## 5단계: 낯선 사람처럼 테스트하기

휴대폰에서, 모바일 데이터로, 시크릿 창에서, 저장된 로그인 없이 라이브 주소를 열어 보세요. 그리고 이렇게 해 보세요.

- 핵심 작업을 처음부터 끝까지 해 보세요.
- 망가뜨려 보세요. 빈 칸, 아주 긴 이름, 뒤로 가기 버튼, 느린 연결로요.
- 방문자가 다크 모드를 쓸 수 있다면 다크 모드에서도 페이지가 제대로 보이는지 확인하세요.
- 한 번도 본 적 없는 사람 한 명에게 링크를 보내고, 도와주지 말고 지켜보세요.

처음 발견한 문제 세 가지를 고치세요. 모든 걸 고치려고 하지 마세요. 완벽한 제품이 아니라, 실제 사람 몇 명이 쓸 수 있을 만큼만 좋으면 돼요.

## 6단계: 기본 분석 도구를 추가하고, 작게 출시하기

누구를 초대하기 전에 개인정보를 존중하는 분석 도구를 설치해서 세 가지 질문에 답할 수 있게 하세요. 몇 명이 왔는지, 몇 명이 핵심 행동을 했는지, 몇 명이 돌아왔는지요. 그런 다음 실제 사람 다섯 명에서 열 명을 여러분이 직접 초대하세요. 공개 출시가 아니에요. 무엇이 헷갈렸는지 물어보세요. 일주일에 한 가지씩 바꾸세요. 이 순환은 [만들고, 측정하고, 배우는 가이드](/ko/blog/build-measure-learn-with-an-ai-team/)에서 설명해요.

## equipe는 어디에 맞을까요, 솔직하게

equipe는 코딩을 못 하는 분들을 위한 AI 스타트업 팀이에요. PM, 엔지니어, 디자이너, QA, 데이터 분석가가 있고, 모두 AI 에이전트예요. 바로 이런 순간을 위해 만들었어요. Claude에서 무언가 작동하고 있고, 그게 고객에게도 작동해야 하는 순간이요. 팀이 호스팅, 데이터베이스, 여러분의 도메인을 설정하고, 여러분은 코드 호스트, 호스팅 서비스, 클라우드 콘솔에 로그인할 일이 없어요. 라이브로 나가거나, 비용이 들거나, 고객에게 닿는 일은 모두 여러분의 승인을 기다려요.

아직 사실이 아닌 부분도 있어요. **Claude에서 한 번에 가져오는 기능은 출시되지 않았어요.** 지금은 아티팩트의 코드를 공유하거나 (또는 그저 무엇을 하는지 설명해 주시면) 팀이 옮겨 드려요. 가입한 뒤에 알게 되시는 것보다 지금 말씀드리는 게 낫다고 생각해서, 홈페이지의 "Coming" 아래에 이걸 적어 두었어요. $5 크레딧으로 카드 없이 무료로 시작할 수 있고, 요금 세부 내용은 [요금 페이지](/ko/pricing/)에서 볼 수 있어요.

직접 하고 싶다면 위의 1단계부터 6단계까지는 우리 없이도 통해요.

## 짧은 체크리스트

- [ ] 전체 소스를 저장해 두었어요
- [ ] 어떤 데이터를 다루는지, 그중 개인정보가 있는지 알아요
- [ ] 샘플 데이터와 브라우저에만 저장하던 방식을 진짜 데이터베이스로 바꿨어요
- [ ] 나 말고 쓰는 사람이 있다면 로그인과 관리자 역할이 있어요
- [ ] 키가 코드가 아니라 비밀 키 저장소에 있어요
- [ ] 내가 통제하는 주소에 올라가 있어요
- [ ] 낯선 사람처럼 휴대폰으로 테스트했어요
- [ ] 분석 도구가 방문, 핵심 행동, 재방문을 세요
- [ ] 실제 사람 다섯 명을 초대했어요

작동하는 아티팩트는 눈에 보이게 된 좋은 아이디어예요. 그걸 서비스로 바꾸는 일은 대부분 배관 작업이고, 배관은 이미 해결된 문제예요. 남은 건 사람들이 여러분이 만든 걸 원하는지 알아내는 일뿐이고, 라이브로 올릴수록 그걸 더 빨리 알게 돼요.
