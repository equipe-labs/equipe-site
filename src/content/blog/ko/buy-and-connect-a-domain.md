도메인은 `yourstudio.com`처럼 사람들이 여러분을 찾으려고 입력하는 이름이에요. 도메인이 없으면 제품은 호스팅 업체가 정한 주소에 머물러요. 테스트할 때는 괜찮지만 고객에게는 어색하죠. 도메인을 사고 연결하는 일은 설정 하나만 틀려도 오류 메시지 없이 빈 화면만 남을 수 있는, 출시 과정에서 몇 안 되는 작업이에요.

이 글은 그 전체 과정을 쉬운 말로 설명해요. 이름 고르는 법, 어디서 사는지, 제품에 어떻게 연결하는지, 끝난 뒤 무엇을 확인하는지까지요. DNS 설정을 한 번도 만져 본 적 없는 분을 위해 썼고, 어떤 도구로 만들었든 도움이 돼요.

<p class="answer"><strong>짧은 답.</strong> 말로 불러도 철자가 떠오르는 짧은 이름을 고르고, 등록 업체에서 내 계정으로 구매하세요. 그다음 호스팅이 알려준 레코드를 추가해 이름이 제품을 가리키게 해요. 설정이 퍼질 때까지 기다리고, 브라우저에 자물쇠가 뜨는지 확인하고, 갱신 알림을 설정하고, 내 로그인 정보를 잘 보관하세요.</p>

## 도메인이란 무엇이고, 알아야 할 세 가지

함께 일하는 서로 다른 세 가지를 떠올려 보세요.

- **도메인 이름**은 `yourstudio.com` 같은 주소예요. 영원히 사는 게 아니라 빌리는 거예요. 유지하려면 보통 매년 비용을 내요.
- **호스팅**은 제품을 저장하고 방문자에게 보내주는 컴퓨터예요. 호스팅에는 자체 기술 주소가 있지만 대부분의 사람은 볼 일이 없어요.
- **DNS**는 인터넷에 "이 이름은 저 호스팅에 있어요"라고 알려주는 전화번호부예요. **레코드**라는 짧은 설정 줄을 추가해서 편집해요.

혼란은 대부분 이 셋을 섞어 생각해서 생겨요. 도메인을 샀다고 호스팅이 생기는 건 아니고, 호스팅에 도메인이 항상 포함되는 것도 아니에요. DNS 레코드가 둘을 이어주어야 비로소 도메인이 제품의 주소가 돼요.

## 이름 고르는 법

이 이름은 앞으로 몇 년 동안 소리 내어 말하고, 명함에 찍고, 메시지에 입력하게 돼요. 나중에 바꾸려면 모든 고객에게 알려야 하니 신중하게 고르세요.

- **짧게.** 글자가 적을수록 오타도 줄어요.
- **한 번 듣고도 철자를 알 수 있게.** "Z가 들어가고 S는 아니에요"라고 설명해야 한다면 다른 이름을 고르세요.
- **하이픈이나 숫자는 피하세요.** 꼭 필요한 경우가 아니라면요. 사람들은 어디에 넣었는지 잊어버려요.
- **전화로 말하기 쉽게.** 친구와 직접 해 보세요.
- **유명한 회사나 아주 비슷한 이름과 헷갈리지 않게.**

정하기 전에 이런 확인을 해 보세요(최신 가격은 등록 업체의 공식 페이지에서 확인하세요).

1. 정확한 이름을 검색 엔진과 앱 스토어에서 검색해 보세요. 비슷한 사업이 나오면 다시 생각해 보세요.
2. 쓰려는 소셜 네트워크에서도 같은 이름이 비어 있는지 확인하세요.
3. 두 사람에게 듣고 입력해 보게 하고, 몇 명이 맞게 쓰는지 세어 보세요.
4. 도메인 끝부분(`.com`, 국가 코드, 새로 생긴 끝부분)을 보세요. 익숙한 끝부분이 기억하기 쉽지만, 지역이나 특정 분야 사용자에게는 국가나 주제별 끝부분이 어울릴 수도 있어요. 끝부분마다 등록 자격 조건이 있을 수 있으니 규칙을 확인하세요.

## 등록 업체와 호스팅: 누가 무엇을 하나요

**등록 업체**는 이름을 등록하고 갱신하는 회사예요. **호스팅**은 제품이 실제로 돌아가는 곳이에요. 둘이 서로 다른 회사인 경우가 많고, 그건 정상이에요.

| | 등록 업체 | 호스팅 |
| --- | --- | --- |
| 하는 일 | 이름의 등록 정보를 보관해요 | 제품을 돌리고 방문자에게 보여줘요 |
| 내는 돈 | 이름을 쓸 권리, 연 단위 | 제품을 온라인에 유지하는 비용 |
| 편집하는 것 | 연락처, 갱신, 잠금 | 제품이 어떤 도메인에 응답할지 |
| DNS 위치 | 보통 여기에 있지만 옮길 수 있어요 | 대신 여기에 있는 경우도 있어요 |

어느 등록 업체를 고르는지보다 더 중요한 게 두 가지 있어요. 첫째, 계정이 **내 것**이어야 해요. 내 이메일 주소로 만들어야 소유자임을 증명할 수 있어요. 둘째, **DNS를 어디서 관리하는지** 알아야 해요. 레코드를 추가하는 곳이 거기니까요.

## 도메인 구매 단계별 안내

1. **내 이메일로 계정을 만들고**, 2단계 로그인이 있으면 켜세요.
2. **이름을 검색해** 사용 가능한지 확인하세요.
3. **결제 전에 갱신 조건을 읽으세요.** 첫해와 이후 연도의 비용이 다를 수 있으니 둘 다 알아두세요.
4. **소유자 정보를 확인하세요.** 등록 정보에 프리랜서나 도구가 아니라 나 또는 내 사업체가 소유자로 적혀 있어야 해요.
5. **자동 갱신**이 있다면 켜고, 유효한 결제 수단을 유지하세요.
6. 등록 업체가 이전 잠금을 제공하면 **도메인을 잠가서** 내 동의 없이 옮겨지지 않게 하세요.
7. **로그인 정보는** 채팅이나 스프레드시트가 아니라 비밀번호 관리자에 저장하세요.

등록 업체가 공개 등록 기록에서 개인 연락처를 숨기는 기능을 제공한다면 켜 보는 것도 좋아요. 제공 여부와 방식은 업체마다 달라서 해당 업체의 안내를 읽어 보세요.

## 도메인을 제품에 연결하기

정확한 값은 호스팅이 알려줘요. 할 일은 그 값을 DNS 설정에 그대로 옮겨 넣는 거예요. 쉽게 말하면 이래요.

- **내 이름을 호스팅으로 가리키는 레코드.** 호스팅은 보통 숫자 형태의 주소나 다른 이름 중 하나를 알려줘요. 둘 다 같은 일을 해요. "누가 내 이름을 입력하면 저쪽으로 보내주세요."
- 보통 **www 버전**을 위한 레코드도 하나 더 있어요. `www.yourstudio.com`과 `yourstudio.com`이 둘 다 열리게 하려는 거예요.
- 가끔 **확인용 레코드**도 있어요. 도메인을 내가 관리한다는 걸 증명하는 짧은 텍스트 줄이에요.

순서는 이래요.

1. 호스팅에 추가해야 할 레코드를 물어보세요. 글로 받아 두세요.
2. 도메인을 관리하는 곳의 DNS 설정을 여세요.
3. 받은 값 그대로 레코드를 하나씩 추가하세요. 다시 타이핑하지 말고 복사해서 붙여 넣으세요.
4. 기존 레코드는 호스팅이 지우라고 할 때만, 그리고 이메일에 쓰이지 않는다는 걸 알 때만 지우세요.
5. 저장하고 기다리세요.

### 변경이 퍼질 때까지 기다리기

DNS 변경은 전 세계 여러 서버로 복사되는 데 시간이 걸려요. 이걸 흔히 **전파**라고 불러요. 몇 분일 때도 있고, 길게는 하루 정도 걸리기도 해요. 기다리는 동안 어떤 사람에게는 새 사이트가, 다른 사람에게는 예전 사이트가 보일 수 있어요. 정상이에요. 조급해서 레코드를 계속 바꾸지 마세요. 바꿀 때마다 기다림이 처음부터 다시 시작돼요.

### 보안 인증서

브라우저의 자물쇠 표시는 연결이 암호화되어 있다는 뜻이에요. 정확히 내 도메인 이름에 발급된 **보안 인증서**에서 나와요. 대부분의 호스팅은 레코드가 올바르게 연결된 뒤에 자동으로 발급해요. 그 전에는 안 돼요. 연결한 뒤에는 시크릿 창에서 주소를 열고 세 가지를 확인하세요. 페이지가 열리는지, 자물쇠가 보이는지, `www` 버전과 일반 버전이 같은 페이지로 가는지요. 브라우저가 경고를 보여주면 고객에게 무시하고 들어가라고 하지 마세요. 레코드를 확인하고 조금 더 기다려 보세요.

## 같은 도메인으로 이메일 쓰기: 주의할 점

`hello@yourstudio.com` 같은 주소는 전문적인 인상을 줘요. 그런데 이메일은 웹사이트를 보여주는 레코드와는 별개의 DNS 레코드를 써요. 주의할 점이 두 가지 있어요.

- **모르는 레코드는 지우지 마세요.** 남은 찌꺼기처럼 보이는 줄이 이메일이 돌아가게 하는 열쇠일 수 있어요.
- **이메일은 웹사이트보다 먼저, 또는 함께 설정하세요.** 나중에 하지 마세요. 이미 그 도메인으로 메일을 받고 있다면 바꾸기 전에 기존 레코드를 적어 두세요.

이메일 서비스도 호스팅처럼 추가할 레코드를 알려줘요. 제품에서 가입 확인 메일 같은 이메일을 보낸다면, 보내는 서비스가 메일이 신뢰받고 스팸함으로 가지 않도록 추가 레코드를 요청하는 경우가 많아요.

## 갱신: 조용히 이름을 잃는 방법

도메인은 보통 1년 같은 기간 단위로 비용을 내요. 만료되면 사이트와 이메일이 멈추고, 유예 기간이 지나면 다른 사람이 등록할 수 있게 돼요. 이렇게 대비하세요.

- 만료일을 달력에 넣고 한 달 전에 알림을 설정하세요.
- 등록 업체의 이메일이 실제로 읽는 주소로 오게 하세요.
- 유효한 카드가 등록되어 있는지, 아니면 누가 결제하는지 알아두세요.
- 등록된 소유자가 누구인지 알아두세요. 다른 사람이 "대신" 등록해 줬다면 내 사업이 그 사람에게 달려 있는 거예요.

## 흔한 실수

- **잘못된 레코드.** 오타이거나 예전 호스팅을 가리키는 레코드예요. 증상은 빈 화면이나 오류예요. 해결: 각 값을 호스팅이 알려준 값과 글자 하나하나 비교하세요.
- **인증서 없음.** 사이트가 경고와 함께 열리거나 아예 안 열려요. 해결: 레코드를 확인하고, 전파를 기다린 뒤, 호스팅의 인증서 상태를 확인하세요.
- **갱신을 깜빡함.** 해결: 달력 알림과 유효한 카드.
- **소유자가 아니라 사용자로만 등록됨.** 프리랜서나 도구가 자기 계정으로 샀다면 내 것임을 증명하기 어려울 수 있어요. 해결: 등록 소유자와 계정 주인이 나 또는 내 사업체여야 해요.
- **이메일 레코드를 삭제함.** 해결: 기존 레코드를 먼저 안전한 곳에 복사해 두세요.

## equipe는 어디에 맞을까요

equipe에서는 위 단계를 직접 하지 않아요. 팀이 고객마다 호스팅, 데이터베이스, 도메인을 설정하고, 여러분은 코드 호스트, 호스팅 서비스, 클라우드 콘솔에 로그인할 필요가 없어요. 팀은 혼자서 도메인을 살 수 없어요. 요청에는 도메인과 가격이 표시되고, 로그인한 팀 멤버만 열 수 있는 승인 페이지로 연결돼요. 승인되었고, 만료되지 않았고, 승인된 가격을 넘지 않을 때만 구매가 허용되며, 승인 한 번에 한 번만 구매돼요. 도메인은 원가로 청구해요. 이런 요청이 어떻게 오는지는 [승인 카드 설명](/ko/blog/approval-cards-explained/)에서, 팀이 혼자 할 수 있는 일과 없는 일은 [안전성 글](/ko/blog/is-equipe-safe-data-money-approvals/)에서 볼 수 있어요.

솔직한 한계도 있어요. 이 글이 모든 경우를 약속하는 건 아니에요. 여러분의 도메인 갱신이나 이전은 어떻게 처리되는지 PM에게 먼저 물어보고 의존하세요. 그리고 직접 알림도 설정해 두세요. 제품이 이 구성을 벗어나 커지면 여러분의 계정으로 옮겨드릴 수 있어요. 모든 걸 직접 하고 싶거나 특정 등록 업체가 꼭 필요하다면, 일반 등록 업체와 호스팅 조합도 똑같이 좋은 선택이에요.

## 도메인 체크리스트

- [ ] 이름이 짧고, 철자를 알 수 있고, 검색 엔진에서 확인했어요
- [ ] 계정이 내 이름, 내 이메일, 2단계 로그인으로 되어 있어요
- [ ] 갱신 조건을 읽었고, 만료 한 달 전 알림을 설정했어요
- [ ] 소유자 정보에 나 또는 내 사업체가 적혀 있어요
- [ ] 호스팅이 준 레코드를 그대로 복사했고, www도 포함했어요
- [ ] 기다린 뒤 시크릿 창에서 자물쇠가 보이는지 테스트했어요
- [ ] 바꾸기 전에 기존 이메일 레코드를 적어 뒀어요
- [ ] 로그인 정보를 비밀번호 관리자에 저장했어요
