AI로 제품을 만들 때 타이핑은 AI가 해 주지만, 용어는 결국 당신 몫이에요. 누군가 "호스팅은 어디 쓰세요?", "API 키 갖고 계세요?"라고 물어볼 텐데, 무슨 뜻인지, 그리고 아무도 지켜보지 않을 때 어떤 일이 조용히 틀어지는지 알아 두면 도움이 돼요.

이 용어집은 코딩을 못 하는 분을 위해 썼어요. 용어마다 같은 네 가지를 답해요. 그게 뭔지, 왜 신경 써야 하는지, 뭐가 잘못될 수 있는지, 그리고 equipe는 어떻게 다루는지(사실로 말할 수 있는 부분만)예요. 용어는 답하는 질문별로 묶었어요.

<p class="answer"><strong>짧은 답.</strong> 제품에는 살 곳(호스팅), 데이터를 둘 곳(데이터베이스), 주소(도메인), 서비스끼리의 비밀번호(키), 변경을 안전하게 내보내는 방법(배포), 무슨 일이 일어나는지 보는 방법(분석)이 필요해요. 이 여섯 가지를 누가 갖고 있고 누가 지켜보는지 답할 수 있다면, 처음 창업하는 분들 대부분보다 제품을 잘 이해하고 있는 거예요.</p>

## 제품이 사는 곳

### 호스팅
- **그게 뭔가요:** 항상 켜져 있고 인터넷에 연결된 컴퓨터예요. 방문자가 언제든 열 수 있도록 제품을 담고 있어요. 가게 건물이라고 생각하면 돼요.
- **왜 신경 써야 하나요:** 호스팅이 멈추면 제품이 아무리 멋져도 오프라인이에요.
- **뭐가 잘못될 수 있나요:** 결제 만료, 게시를 막는 플랜, 약관 변경 같은 일이 있어요. 무료 플랜은 방문할 수 있는 사람을 제한하기도 해요.
- **equipe는 어떻게 다루나요:** 팀이 Cloudflare에 고객당 하나의 프로젝트로 호스팅을 설정해요. 코드 호스트, 호스팅 서비스, 클라우드 콘솔에 로그인할 일이 없어요. 제품이 그 범위를 넘어서면 당신의 계정으로 옮길 수 있어요. Team 플랜에는 사이트 호스팅이 포함돼 있고, 월 $19의 호스팅 전용 플랜은 팀이 쉬는 동안에도 제품, 사이트, 도메인, 저장 공간을 계속 켜 둬요. [요금](/ko/pricing/)을 확인해 보세요.

### 백엔드와 프런트엔드
- **그게 뭔가요:** 프런트엔드는 방문자가 보고 누르는 부분이에요. 페이지, 버튼, 양식 같은 것이죠. 백엔드는 막 뒤에서 정보를 기억하고, 이메일을 보내고, 누가 로그인했는지 확인하는 부분이에요.
- **왜 신경 써야 하나요:** 백엔드 없는 예쁜 프런트엔드는 예약을 저장하지도, 고객을 기억하지도 못해요. "다 된 것 같은데 저장이 안 돼요"라는 말은 대개 이게 이유예요.
- **뭐가 잘못될 수 있나요:** 프로토타입에는 프런트엔드만 있을 수 있어요. 새로고침하기 전까지는 잘 되는 것 같다가, 데이터가 사라져요.
- **equipe는 어떻게 다루나요:** 팀이 둘 다 만들고, 백엔드에 필요한 호스팅과 데이터베이스도 설정해요.

## 데이터가 사는 곳

### 데이터베이스
- **그게 뭔가요:** 제품이 기억하는 정보를 정리해 두는 저장소예요. 고객, 주문, 예약, 가입 정보 같은 것이죠. 제품이 스스로 읽고 쓰는, 아주 엄격한 스프레드시트를 떠올려 보세요.
- **왜 신경 써야 하나요:** 고객의 정보가 들어 있어요. 잃어버리거나 엉뚱한 사람이 읽게 되는 건 가장 나쁜 실수예요.
- **뭐가 잘못될 수 있나요:** 접근할 수 없는 곳에 데이터가 있거나, 실수로 지워지거나, 되돌릴 사본이 없거나, 비공개 정보가 다른 사람에게 보여요.
- **equipe는 어떻게 다루나요:** 팀이 프로젝트의 일부로 데이터베이스를 설정해요. 각 팀은 다른 고객과 분리된 격리된 머신에서 돌아가고, 삭제는 항상 당신의 승인을 기다려요. 백업이나 가동 시간에 대한 약속은 공개하지 않아요. 그러니 있다고 가정하지 마세요. 전체 목록은 [equipe는 안전한가요?](/ko/blog/is-equipe-safe-data-money-approvals/)에서 읽어 보세요.

## 사람들이 찾아오는 길

### 도메인
- **그게 뭔가요:** yourname.com 같은 웹 주소예요. 등록 대행 업체에서 보통 1년 단위로 빌려요.
- **왜 신경 써야 하나요:** 브랜드이자 이메일 주소의 바탕이에요. 만료되거나 다른 사람이 갖고 있으면 둘 다 잃을 수 있어요.
- **뭐가 잘못될 수 있나요:** 프리랜서나 대행사 계정으로 등록하거나, 갱신을 잊거나, 고객이 헷갈릴 비슷한 이름을 사는 경우예요.
- **equipe는 어떻게 다루나요:** 팀은 도메인을 혼자 살 수 없어요. 요청에는 도메인과 가격이 표시되고, 당신 팀의 로그인한 구성원만 열 수 있는 승인 페이지로 이어져요. 승인되었고, 만료되지 않았고, 승인한 가격을 넘지 않을 때만 구매가 진행돼요. 승인 한 번으로는 한 번만 살 수 있어요. 도메인은 승인한 연 가격으로 크레딧에서 결제돼요. 자세한 과정은 [도메인 구매하고 연결하기](/ko/blog/buy-and-connect-a-domain/)에 있어요.

### DNS
- **그게 뭔가요:** 인터넷의 전화번호부예요. DNS 레코드가 도메인이 어느 호스팅을 가리켜야 하는지, 이메일은 어디로 가야 하는지 세상에 알려 줘요.
- **왜 신경 써야 하나요:** 제품 자체는 멀쩡해도 레코드 하나가 틀리면 사이트나 이메일이 멈출 수 있어요.
- **뭐가 잘못될 수 있나요:** 엉뚱한 레코드를 고치거나, 변경이 퍼지는 데 시간이 걸려서 나한테는 멀쩡한데 고객에게는 고장 난 것처럼 보여요.
- **equipe는 어떻게 다루나요:** 호스팅 서비스나 클라우드 콘솔에 직접 로그인할 일이 없어요. 도메인이 승인되고 구매되면 팀이 연결을 마쳐요.

### SSL 인증서
- **그게 뭔가요:** 주소가 https로 시작하고 자물쇠 표시가 보이게 하는 것이에요. 방문자와 사이트 사이의 연결이 비공개이고, 사이트가 말하는 그 사이트가 맞다는 뜻이에요.
- **왜 신경 써야 하나요:** 없으면 브라우저가 안전하지 않은 사이트라고 경고하고, 사람들이 떠나요.
- **뭐가 잘못될 수 있나요:** 인증서가 만료되거나 도메인과 맞지 않으면 무서운 경고 화면이 떠요.
- **equipe는 어떻게 다루나요:** 인증서에 대해서는 [보안 페이지](/ko/security/)에 적힌 것 이상으로 따로 주장하지 않아요.

## 키와 접근 권한

### API
- **그게 뭔가요:** 한 프로그램이 다른 프로그램에 무언가를 요청하는 정해진 방법이에요. 제품이 이메일 서비스에 메시지 발송을 요청하고, 결제 서비스에 카드 결제를 요청해요. 이런 서비스마다 API가 있어요.
- **왜 신경 써야 하나요:** 이메일, 결제, 지도 같은 유용한 기능 대부분은 API로 연결하는 다른 회사의 서비스예요. 하나 붙일 때마다 비용, 규칙, 위험이 늘어요.
- **equipe는 어떻게 다루나요:** 메시지를 보내거나 비용이 드는 일은 당신의 승인을 기다려요. 연동 목록을 내세우지는 않아요.

### API 키 / 시크릿
- **그게 뭔가요:** 요청이 당신에게서 왔다는 걸 서비스에 증명하는 비밀번호 같은 문자열이에요. 은행 비밀번호처럼 다루세요.
- **왜 신경 써야 하나요:** 키를 가진 사람은 누구나 당신인 척 행동하고 비용을 쓸 수 있어요.
- **뭐가 잘못될 수 있나요:** 키를 채팅, 문서, 공개된 코드 페이지에 붙여 넣으면 낯선 사람이 찾아내요. 하나의 키를 모든 곳에 쓰면 한 번의 유출로 전부 노출돼요.
- **equipe는 어떻게 다루나요:** 키와 비밀번호는 별도의 암호화된 저장소에 있고, AI에게도 채팅에도 보이지 않아요. 다른 곳에서 만들 때의 좋은 규칙 하나. 메시지에 키를 입력한 적이 있다면 교체하세요.

## 변경이 고객에게 닿는 길

### 저장소(repository)
- **그게 뭔가요:** 제품의 코드와 전체 기록을 담은 폴더예요. 저장된 변경마다 누가, 왜 했는지 남아요. 나중에 개발자가 이어받을 수도 있어요.
- **equipe는 어떻게 다루나요:** 각 팀 구성원은 프로젝트의 자기 사본에서 자기 브랜치로 작업하고, 당신이 말하기 전에는 아무것도 메인 제품에 합쳐지지 않아요. 작업은 담당자, 상태, 기록이 있는 티켓으로 관리돼요.

### 버전과 롤백
- **그게 뭔가요:** 버전은 제품이 저장된 한 시점의 상태예요. 롤백은 변경이 문제를 일으켰을 때 이전 버전으로 되돌리는 거예요.
- **뭐가 잘못될 수 있나요:** 돌아갈 이전 버전이 없거나, 되돌려도 데이터 변경은 취소되지 않는 경우예요.
- **equipe는 어떻게 다루나요:** 각 티켓은 작업 기록을 남겨요. 백업에 대한 약속은 공개하지 않으니, 복원에 기대기 전에 먼저 물어보세요.

### 배포
- **그게 뭔가요:** 완성된 변경을 만드는 쪽 작업 공간에서 고객이 보는 실제 제품으로 옮기는 일이에요. 게시나 출시라고도 해요.
- **왜 신경 써야 하나요:** 실수가 공개되는 순간이에요.
- **뭐가 잘못될 수 있나요:** 덜 끝난 걸 내보내는 일이에요.
- **equipe는 어떻게 다루나요:** 게시는 항상 당신의 승인을 기다려요. 선택지, 추천, 예상 비용이 담긴 짧은 카드로 보여 드려요.

### 미리보기
- **그게 뭔가요:** 고객에게 닿기 전에 열어 보고 테스트할 수 있는 변경의 비공개 사본이에요.
- **뭐가 잘못될 수 있나요:** 열어 보지도 않고 승인하는 경우예요.
- **equipe는 어떻게 다루나요:** 클라우드 웹 앱에서 미리보기 링크로 작업을 따라갈 수 있어요.

### 환경(environment)
- **그게 뭔가요:** 제품이 돌아가는 별도의 공간이에요. 예를 들어 비공개 테스트 사본과 실제 제품이죠. 같은 제품이어도 환경마다 설정, 키, 데이터가 다를 수 있어요.
- **왜 신경 써야 하나요:** 테스트하면서 실제 고객 데이터나 실제 결제 키를 쓰는 데서 사고가 나요.
- **뭐가 잘못될 수 있나요:** 테스트 설정이 실제 제품에 들어가거나, 그 반대가 되는 경우예요.
- **equipe는 어떻게 다루나요:** 미리보기 링크와, 공개되기 전의 승인 단계까지만 말씀드려요. 더 세부적인 건 직접 물어보세요.

## 무슨 일이 일어나는지 아는 법

### 분석(analytics)
- **그게 뭔가요:** 방문자가 하는 일을 세는 거예요. 몇 명이 왔는지, 어떤 페이지를 썼는지, 어디서 떠났는지요.
- **뭐가 잘못될 수 있나요:** 필요 이상으로 개인 정보를 모으거나, 아무도 보지 않는 숫자만 쌓여요.
- **equipe는 어떻게 다루나요:** equipe로 만든 제품의 분석은 쿠키를 쓰지 않고 IP 주소를 저장하지 않아요. 두 글자 국가 코드와, 방문자 브라우저에 저장되는 무작위 익명 ID만 남기고, 이벤트는 180일 뒤에 삭제돼요. 횟수, 퍼널, 재방문을 볼 수 있고, 변형과 목표 이벤트로 하는 간단한 A/B 테스트도 있어요. 앱에는 비용 보기도 있어요. 이번 달 사용액, 월말 예상 합계, 월 한도와의 비교를 보여 줘요. [작은 제품을 위한 지표](/ko/blog/metrics-for-a-small-product/)도 읽어 보세요.

## 체크리스트: 어떤 제품에든 물어볼 여섯 가지

| 질문 | 좋은 답은 이렇게 들려요 |
| --- | --- |
| 어디에 살고 있나요(호스팅)? | 이름이 있는 서비스이고, 내가 접근할 수 있거나 옮겨 둔 계정 |
| 데이터는 어디 있나요(데이터베이스)? | 어디인지, 누가 읽을 수 있는지, 어떻게 지워지는지 알고 있다 |
| 도메인은 누구 이름으로 되어 있나요? | 내 이름, 갱신일도 알고 있다 |
| 키는 어디 있나요? | 저장소 안, 채팅이나 문서에는 절대 없다 |
| 변경이 공개되기 전에 무슨 일이 있나요? | 미리보기, 그다음 내 승인 |
| 사람들이 쓰는지 어떻게 아나요? | 필요 없는 건 모으지 않고도 횟수를 볼 수 있다 |

## equipe는 어디에 맞을까요

equipe는 코딩을 못 하는 분이 이 대부분을 직접 관리하지 않아도 되도록 만들었어요. 팀이 호스팅, 데이터베이스, 도메인을 처리하고, 키는 암호화된 저장소에 있고, 공개되거나 비용이 들거나 고객에게 닿는 일은 당신을 기다려요. 제품이 그 설정을 넘어서면 당신의 계정으로 옮길 수 있어요.

아직 없는 것: 데이터베이스와 도메인까지 포함한 Claude에서의 원스텝 가져오기예요. 지금은 코드를 공유하거나 설명해 주시면 팀이 옮겨 드려요. 백업이나 가동 시간 약속, SOC 2나 ISO 27001 주장, 공개 상태 페이지도 아직 없어요. 이런 게 필요하다면 지금의 equipe는 맞는 선택이 아니에요.
