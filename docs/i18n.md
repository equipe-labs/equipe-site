# Translating the site

The landing page is served in up to eight languages. English is the source; every other
language is one file in `src/i18n/`. This page is all you need to add one.

| Code    | URL        | `<html lang>` | Name shown in the menu |
| ------- | ---------- | ------------- | ---------------------- |
| `en`    | `/`        | `en`          | English (source)       |
| `ko`    | `/ko/`     | `ko`          | 한국어                 |
| `ja`    | `/ja/`     | `ja`          | 日本語                 |
| `zh-CN` | `/zh-cn/`  | `zh-CN`       | 简体中文               |
| `es`    | `/es/`     | `es`          | Español                |
| `pt-BR` | `/pt-br/`  | `pt-BR`       | Português (Brasil)     |
| `de`    | `/de/`     | `de`          | Deutsch                |
| `fr`    | `/fr/`     | `fr`          | Français               |

(The table lives in `src/i18n/locales.ts`. Add a language there only if the list above changes.)

## Add a language

1. Copy `src/i18n/en.ts` to `src/i18n/<code>.ts` — the file name is the code from the table
   (`ko.ts`, `zh-CN.ts`, `pt-BR.ts`).
2. Replace the file's header with the following, and translate every value:

   ```ts
   import type { Messages } from './en';

   const ko: Messages = {
     meta: { /* … */ },
     // … same keys, same order as en.ts
   };

   export default ko;
   ```

   Do not rename or remove keys, and keep the number of items in lists (`how.cards`,
   `who.points`, `faq.items`) the same as in English.
3. Run `npm run build`. The page `/<slug>/` is generated, the language shows up in the
   language menu, and it is added to every page's `hreflang` set and to the sitemap.
4. Open `dist/<slug>/index.html` (or `npm run dev`) and read the page.

A language **without** a file has no page: nothing is generated, listed or linked for it.
Never fill a file with English text to "reserve" a language; that creates a duplicate page.

## The build checks your file

`npm run build` runs `astro check` and then a structural comparison against `en.ts`. It fails when

- a key is missing or unknown, a value has the wrong type, or a value is an empty string;
- a list has a different length than the English one.

The error names the key, for example `ko.meta.ogTitle: expected a string`.

## What each group of keys is

| Group    | Where it appears |
| -------- | ---------------- |
| `meta`   | `<title>`, meta description, Open Graph / Twitter title, description and image alt text. Keep `title` ≈ 60 and `description` ≈ 155 characters. |
| `ui`     | Skip link, button labels, language menu label, and the "view this page in …" banner. |
| `nav`, `hero`, `how`, `who`, `start`, `footer` | Page sections, top to bottom. |
| `faq`    | The visible FAQ **and** the `FAQPage` structured data, from the same strings. |

Notes:

- Markup inside strings: `` `backticks` `` render as inline code, `**double asterisks**` as bold.
  Keep them around the same words as the English. Do not translate what is inside backticks
  when it is a command, file name or product name (`claude`, `originator: equipe`).
- `start.runCode` is a shell block: translate only the `# comments`, never the commands.
- `ui.bannerText` must contain `{language}`; it is replaced by the target language's own
  name. The banner is shown to visitors whose browser prefers *this* language, so write it
  in this language ("이 페이지를 {language}로 보기").
- Follow `design/i18n/glossary.md` (terms, tone, SEO keywords per language) if it is present on your branch.
- The social image (`/og.png`) is shared by all languages and carries English text.

## What the build generates for each language

You do not write any of this; it comes from the file's existence.

- `<html lang>`, a self-referencing `canonical`, `hreflang` links for **every** available
  language plus `x-default` (→ English), `og:locale` and `og:locale:alternate`.
- `inLanguage` on the `WebSite`, `SoftwareApplication` and `FAQPage` JSON-LD, with the
  translated description and FAQ.
- Sitemap entries with `xhtml:link` alternates (`@astrojs/sitemap` `i18n` option in `astro.config.mjs`).
- A language menu made of plain `<a>` links (names written in their own language), and a
  dismissible banner that *suggests* the visitor's browser language. It never redirects, and
  once dismissed (or a language is chosen from the menu) it stays away (`localStorage`).

## Fonts

No CJK webfont is shipped. Korean, Japanese and Simplified Chinese fall back to system fonts
via `:lang()` rules in `src/styles/global.css`. If a webfont is ever added, it must be a
subset and loaded only on that language's pages, so the English page's Lighthouse score
stays at 100.
